# 백오피스 썸네일 업로드 열기 (#377)

백오피스에서 이미지를 **골라서** 올릴 수 있게 만드는 절차다. **코드 배포만으로는 안 열린다** — 버킷과
IAM 자격증명은 코드가 만들 수 없다.

| # | 무엇 | 담당 | 없으면 |
|---|---|---|---|
| 1 | S3 버킷 생성 (공개 읽기 · presigned 쓰기) | **사람** | 업로드 주소 발급이 `502 CURATION-009` |
| 2 | 업로드 전용 IAM 사용자·키 발급 | **사람** | 위와 같음 |
| 3 | 버킷 CORS 허용 | **사람** | 발급은 되는데 브라우저의 `PUT` 이 CORS 로 막힌다 |
| 4 | 배포 환경변수 5개 등록 | **사람** | 위와 같음 |

**열기 전에도 배포는 나갈 수 있다.** 자격증명이 없으면 어댑터가 비활성으로 뜨고 발급만 실패한다 —
부팅과 나머지 기능은 그대로고, 어드민은 지금까지처럼 **주소 붙여넣기** 탭으로 등록한다.

---

## 1. 버킷

새로 만든다. 기존 버킷에 얹지 않는다 — 이 버킷의 객체는 **공개 읽기**라, 공개해도 되는 것만 들어가야
한다.

| 항목 | 값 |
|---|---|
| 이름 | 예: `offway-admin-assets`. **점(`.`)을 넣지 않는다** — 아래 참고 |
| 리전 | `ap-northeast-2` (서울) |
| 퍼블릭 액세스 차단 | **해제** — 객체를 공개로 읽어야 앱이 썸네일을 그린다 |
| 버전 관리 | 꺼도 된다. 덮어쓰기가 없다(키에 UUID 가 들어간다) |

> **버킷 이름에 점을 넣지 않는다.** 공개 주소를 따로 주지 않으면 서버가
> `https://{버킷}.s3.{리전}.amazonaws.com` 형식으로 만드는데, 이름에 점이 있으면 그 호스트명이
> `*.s3.{리전}.amazonaws.com` 와일드카드 인증서와 맞지 않아 **브라우저가 TLS 에서 막는다.** 업로드는
> 성공하고 저장까지 끝난 뒤에야 이미지가 안 열리는 것으로 드러난다. 점이 필요하면 `S3_PUBLIC_BASE_URL`
> 을 반드시 채운다 — 서버가 부팅 로그에 그 경고를 남긴다.

**쓰기는 presigned 로만 들어온다.** 버킷 정책은 읽기만 공개하고 쓰기는 열지 않는다.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadCurationThumbnails",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::offway-admin-assets/curation/*"
    }
  ]
}
```

`curation/*` 로 좁힌 이유는 나중에 이 버킷에 **공개하면 안 되는 것**을 넣게 될 때 정책을 다시 안 고쳐도
되게 하려는 것이다. 서버가 만드는 키가 `curation/{uuid}.{ext}` 다.

## 2. IAM

업로드 전용 사용자를 따로 만든다. 다른 용도의 키를 재사용하면, 그 키를 돌릴 때 이 기능이 함께 멈춘다.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::offway-admin-assets/curation/*"
    }
  ]
}
```

**`s3:PutObject` 하나면 된다.** 서버는 올리지도, 지우지도, 목록을 보지도 않는다 — 서명만 만든다.
`s3:DeleteObject` 를 주면 그 권한이 서명에도 실릴 수 있는 자리가 생기므로 주지 않는다.

액세스 키를 발급해 다음 단계에 쓴다.

## 3. CORS

브라우저가 **우리 서버가 아니라 S3 로 직접** `PUT` 하므로, 버킷이 우리 도메인을 허용해야 한다. 이걸
빼면 발급까지는 성공하고 업로드만 조용히 막힌다 — 콘솔에만 CORS 오류가 뜬다.

```json
[
  {
    "AllowedOrigins": ["https://api.offway.cloud"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["Content-Type"],
    "MaxAgeSeconds": 3000
  }
]
```

`AllowedHeaders` 에 `Content-Type` 이 있어야 한다. 서명에 그 헤더가 들어 있어 브라우저가 반드시 보낸다.

> 로컬(`http://localhost:8080`)에서도 시험하려면 그 origin 을 함께 넣는다. 운영 버킷에 로컬 origin 을
> 남겨 두지 않는다.

## 4. 환경변수

배포 워크플로우(`.github/workflows/deploy.yml`)와 GitHub 시크릿에 넣는다.

| 이름 | 값 | 비우면 |
|---|---|---|
| `S3_BUCKET` | 버킷 이름 | 업로드 비활성 |
| `S3_REGION` | `ap-northeast-2` | 기본값이 이미 서울이라 안 넣어도 된다 |
| `S3_ACCESS_KEY` | 2번의 액세스 키 | 업로드 비활성 |
| `S3_SECRET_KEY` | 2번의 시크릿 | 업로드 비활성 |
| `S3_PUBLIC_BASE_URL` | CloudFront 를 앞에 둘 때만 | 버킷 기본 주소를 쓴다 |

넷(`BUCKET`·`REGION`·`ACCESS_KEY`·`SECRET_KEY`) 중 **하나라도 비면** 업로드가 비활성이다. 반쯤 채워
두면 서명은 만들어지는데 S3 가 거절해, 어드민이 올리기를 누른 뒤에야 실패를 알게 된다. 그래서 서버가
발급 단계에서 미리 끊는다.

## 확인

1. 백오피스에서 링크를 하나 열고 **썸네일 > 업로드** 탭에서 이미지를 고른다
2. "올렸습니다" 가 뜨면 **저장**을 누른다 — 올리기만 하고 저장하지 않으면 아무 데도 안 걸린다
3. 목록의 썸네일과 앱 카드에 그 이미지가 보이면 끝

실패하면 문구가 사유를 그대로 말한다.

| 문구 | 무엇이 빠졌나 |
|---|---|
| 이미지 저장소를 사용할 수 없습니다 | 4번 환경변수 (또는 넷 중 하나가 빔) |
| `S3 403` | 2번 IAM 정책의 Resource 가 키와 안 맞음 |
| 콘솔에 CORS 오류 | 3번 |
| 업로드는 되는데 이미지가 안 열림 | 버킷 이름에 점이 있고 `S3_PUBLIC_BASE_URL` 이 빔 (1번 참고) |

## 남는 것 — 버려지는 오브젝트

주소만 받고 저장하지 않거나, 올린 뒤 폼을 닫으면 **아무 데서도 참조하지 않는 오브젝트**가 남는다.
지금은 그대로 둔다 — 어드민 몇 명이 쓰는 화면이라 쌓이는 양이 적고, 지우려면 "저장 안 된 오브젝트" 를
판정하는 배치가 따로 필요한데 그 값이 아직 비용보다 크지 않다.

양이 눈에 띄게 늘면 버킷 수명 주기 규칙(예: `curation/` 아래 30일 이상 된 것 중 참조 없는 것)을 그때
정한다.
