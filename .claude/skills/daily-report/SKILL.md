# OffWay 일일 리포트

그날 한 백엔드 작업을 **한 작업 = 한 줄**로 정리한 표로 만든다. 읽는 사람은 백엔드를 모르는 팀원(디자인·프론트·기획)이다.
**UI·디자인에 힘주지 않는다. 표와 내용에 집중한다.**

## 핵심 원칙

- **각 행은 순번 · 작업 제목 · 세부, 딱 셋이다.** 그 이상의 장식(색 테마, 카드, 히어로, 진행바)은 만들지 않는다. 세부 열 제목은
  "이 작업으로 사용자가 할 수 있는 것".
- **세부는 "이 작업으로 사용자가 무엇을 할 수 있는지"로 쓴다.** `port/adapter`·`502`·`enum` 같은 코드 용어가 아니라, 사용자가
  화면에서 **무엇을 하면(누르면·고르면·입력하면) 무엇을 얻는지**를 구체 예시와 함께 적는다.
  - 예(#87): "코스 생성으로 나온 코스에서 특정 장소를 누르면, 그 장소의 '대한민국 구석구석' 한 줄 소개가 함께 뜬다
    (예: 완도타워 → *바다 위에 뜬 낭만, 완도의 랜드마크*)."
  - 예(#88): "장소를 누르면 무장애(배리어프리) 정보를 볼 수 있다 — 휠체어 대여·장애인 화장실·음성안내·수유실 등을 분류별로."
- **지어내지 않는다.** 표에 올리는 건 그날 실제로 한 것(머지된 PR·닫힌 이슈·커밋)만. 근거 없는 건 올리지 않는다.
- **제목은 작업을 그대로, 세부는 사용자 관점으로.** 제목은 PR 제목 수준의 담백한 한 줄(예: "장소 상세에 구석구석 캐치프레이즈
  추가"), 세부에서 그게 사용자에게 어떤 경험이 되는지를 푼다.

## 절차

### 1. 오늘 한 일을 수집한다 (근거 기반)

그날 날짜(KST)를 확인하고, 추측하지 말고 아래에서 사실을 긁는다:

```bash
gh pr list --repo <owner/repo> --state merged --search "merged:>=<오늘날짜>" --json number,title,body
gh issue list --repo <owner/repo> --state closed --search "closed:>=<오늘날짜>" --json number,title
git log --since="<오늘날짜> 00:00" --pretty="%s"
```

PR 본문(`body`)·명세 변경은 "무슨 API/기능이 생겼는지"의 단서로 쓴다. 사용자가 대화에서 이미 그날 한 일을 말했다면 그걸 1순위
사실로 삼는다. 각 PR/이슈가 표의 한 행이 된다(너무 잘면 관련된 것끼리 한 행으로 묶어도 된다).

### 2. 각 작업을 한 행으로 재구성한다

행마다:

- **순번**: 1, 2, 3 … (그날 순서 또는 임팩트 순).
- **작업**: 담백한 제목 한 줄(PR 제목 수준).
- **세부**: 사용자가 무엇을 하면 무엇을 얻는지 + 구체 예시 1개. 1~2문장. "되는 것" 중심으로.

세부를 쓸 때 스스로 물어본다: *이 작업 덕에 사용자가 화면에서 새로 할 수 있게 된 것이 뭔가? 어떤 데이터·경험이 붙나?*
답이 안 나오면(순수 내부 리팩터·인프라) 세부에 "화면 변화는 없고, ○○가 더 견고해짐"처럼 솔직히 적는다.

### 3. 표로 렌더한다

아래 최소 템플릿에 채운다. `docs/specs/progress-report-<MMDD>.html` 로 저장하고 연다:

```bash
open docs/specs/progress-report-<MMDD>.html
```

세부 줄이 길어 세로로 넘쳐도 괜찮다(캡처 한 화면에 집착하지 않는다) — **내용이 우선**이다. 사용자에게 파일 경로를 알려주고,
문구 조정 요청을 받으면 반영한다. 마크다운 표로 달라고 하면 같은 3열(순번·작업·세부)로 준다.

## 최소 템플릿 (`assets/report-template.html`)

`assets/report-template.html` 이 정본이다. 복제해 헤더 날짜·건수와 `<tbody>` 행만 갈아끼운다. 스타일은 가독성 최소한만
(읽기 좋은 표) — 색 테마·폰트 놀이·카드 없음. 행이 늘면 `<tr>` 를 추가한다.

## 톤

담백하고 자신감 있게. 과장·이모지 남발 금지. "됐다/실제로 돈다"는 근거 있을 때만. 비개발자가 표만 훑어도 "오늘 사용자에게 뭐가
생겼는지" 파악되면 성공.
