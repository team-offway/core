# OffWay 개발일지

그날 한 작업을 **한 장**으로 정리한다. 읽는 사람은 **팀 전체**다 — 디자인·기획도 보고, 개발도 본다.

**결과만 적지 않는다. 무엇이 문제였는지를 함께 적는다.** "푸시 알림이 잠금화면에 뜬다" 는 결과만 남기면,
12일 동안 안 보이고 있었다는 것도 발송은 성공으로 집계되고 있었다는 것도 사라진다. 그 사실이 그날 한 일의
값어치이자, 다음에 같은 함정을 피하는 근거다.

## 핵심 원칙

- **카드 제목은 문제 서술이다.** `…었다` 로 끝난다. "푸시 알림 배너 추가"(X) → **"붙여 둔 푸시가 12일 동안
  아무에게도 안 보였다"**(O). 무엇을 했는지는 불릿이 말한다.
- **지어내지 않는다.** 지표 카드의 숫자는 **실측·집계된 것만** 올린다. 세어 보지 않은 수를 그럴듯하게 적지
  않는다. 근거는 머지된 PR·닫힌 이슈·커밋·그날의 실측이다.
- **채울 것이 없으면 칸을 비우지 말고 카드 수를 줄인다.** 형식을 채우려고 없는 일을 만들지 않는다.
- **자정을 넘긴 작업은 시작일로 묶는다.** 밤 11시에 시작해 새벽 1시에 머지한 것은 그 전날 일이다. 자정으로
  끊으면 하루가 반 토막 나 보인다(실제로 8/30 리포트가 그렇게 2건짜리가 됐다).
- **리뷰에서 고친 것·고치다 만난 것도 그날의 일이다.** 화면 변화가 없어도 "더 한 작업들" 에 남긴다 — 그게
  하루의 절반인 날이 많다.
- **화면 변화가 없으면 그렇게 적는다.** "화면 변화는 없다" 로 시작하고 무엇이 나아졌는지 잇는다. 정당한
  답이지 회피가 아니다.

## 한 장의 구성

| 자리 | 무엇 | 개수 |
|---|---|---|
| 머리 | `offway 개발일지 · core` + 큰 날짜·요일 | — |
| 리드 | 그날을 한두 문장으로. 핵심 수치를 강조색으로 | 1 |
| **지표 카드** | 그날을 숫자로 — PR 수·기간·건수·규모 | 4 |
| **본 카드** | 문제 서술 제목 + 태그(`fix`·`#358`·`머지`) + 불릿 3~4개 | 3~4 |
| **더 한 작업들** | `#PR · 제목` + 한 문단. 리뷰 지적·고치다 만난 것 | 3~6 |
| **이번 주 중점** | 어두운 블록. 주차 + 두 칼럼 산문 | 2칼럼 |
| 바닥 | 스택 표기 · 날짜 · 다룬 PR 번호 | — |

## 절차

### 1. 사실을 긁는다 — 추측하지 않는다

작업 시작일(KST)을 정하고, **자정을 넘겼으면 그 전날로 묶는다**.

```bash
# 작업 세션 구간으로 본다 (자정 넘긴 머지를 놓치지 않게)
gh pr list --state merged --search "merged:<시작>..<끝>" --json number,title,labels
gh issue list --state closed --search "closed:>=<시작>" --json number,title
git log --since="<시작>" --pretty="%h %cI %s" origin/dev
```

숫자를 쓸 거면 그 자리에서 센다 — 테스트 수, 처리한 리뷰 지적 수, 실측값. **대화에서 이미 잰 값이 있으면
그것을 1순위로 쓴다.**

### 2. 카드로 재구성한다

**본 카드** 하나가 보통 PR 하나다. 쓰기 전에 스스로 묻는다:

- *무엇이 문제였나* → 제목
- *왜 그게 문제였나* → 첫 불릿
- *어떻게 알았나 / 얼마나였나* → 숫자가 있는 불릿
- *무엇을 정했나* → 판단이 갈렸던 자리

**더 한 작업들** 은 리뷰 지적·고치다 만난 함정·실측이다. 한 문단으로 끝낸다.

**이번 주 중점** 은 그날 하루가 아니라 **주 단위 방향**이다. 이번 주에 반복해서 나온 결이 있으면 그것을
이름 붙인다("붙여 놓고 안 보이던 것들을 잇는다").

### 3. 렌더하고 캡처한다

`assets/report-template.html` 을 `docs/specs/progress-report-<MMDD>.html` 로 복제해 내용만 갈아끼운다.

```bash
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$CHROME" --headless --disable-gpu --hide-scrollbars \
  --screenshot="$(pwd)/docs/specs/progress-report-<MMDD>.png" \
  --window-size=2000,<내용높이> --force-device-scale-factor=1.5 \
  "file://$(pwd)/docs/specs/progress-report-<MMDD>.html"
```

**높이는 내용에 맞춘다.** 한 번 크게 찍어 보고 아래 여백만큼 줄여 다시 찍는다.

**워크트리에서 작업 중이면 메인 체크아웃에도 복사한다.** 사용자가 그쪽 폴더를 열기 때문에, 안 하면 낡은
파일을 보게 된다(실제로 그랬다).

```bash
cp docs/specs/progress-report-<MMDD>.png <메인체크아웃>/docs/specs/
open -R <메인체크아웃>/docs/specs/progress-report-<MMDD>.png
```

**리포트 파일은 커밋하지 않는다** — 기능 PR 에 섞이면 안 되는 산출물이다(`/commit` 의 제외 대상).

## 톤

담백하고 자신감 있게. 과장·이모지 금지. **"됐다/실제로 돈다"는 근거 있을 때만.** 강조색은 문장마다 뿌리지
말고 **그 카드의 핵심 한 곳**에만 쓴다 — 다 강조하면 아무것도 강조되지 않는다.

숫자에는 단위를, 비교에는 전후를 붙인다(`16 → 25곳`, `12일`, `5곳 / 89`).
