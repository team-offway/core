붙여 둔 푸시가 12일 동안 아무에게도 안 보였다

fix#358머지
  • data 만 실은 메시지는 iOS 가 silent push 로 취급합니다. 백그라운드·종료 상태에서 아무것도 안 그리고, 전달 자체가 버려지기도 합니다.
  • 그런데 이 알림은 전날 20시·다음 날 20시 배치입니다 — 정확히 그 상태에서 필요합니다.
  • 발송은 SENT 로 성공했고 CI 도 초록이었습니다. 보내는 내용 자체를 아무도 안 보고 있었습니다.
  • "문구를 서버가 들지 않는다"를 폐기한 게 아니라 범위를 바로잡았습니다 — 알림함은 30일 남아 굳고, 배너는 지나가면 끝입니다.

알림이 어느 여행 얘기인지 말하지 못했다

feat#359머지
  • 코스를 여러 개 담아 둔 사람에게 "여행, 다녀오셨나요?" 는 어느 여행인지 알 수 없는 알림입니다.
  • 특히 연차를 기록해 달라는 요청이라, 어느 여행인지 모르면 눌러 보기 전까지 판단이 안 됩니다.
  • 앱이 코스를 직접 조회하면 알림 5건에 요청 5번이고, 지워진 코스는 404 라 그 줄만 빕니다. 서버가 한 페이지에 조회 두 번으로 채웁니다.
  • 지역명은 문구가 아니라 데이터라, "문구는 앱이 소유한다"는 원칙은 그대로입니다.

값 하나 고치려면 배포를 해야 했다

feat#354머지
  • 앱 네 화면에 뜨는 외부 링크를 추가·수정·삭제하는 API 를 붙였습니다. 어떤 화면에·언제부터 언제까지·지금 켤지를 그 자리에서 정합니다.
  • 어드민은 소셜 로그인 그대로 쓰고 화이트리스트에 있으면 역할만 올립니다 — 별도 로그인은 지켜야 할 자리를 하나 더 만듭니다.
  • GET 도 막았습니다. 어드민 목록에는 미공개 항목이 전부 있어, 읽기를 열면 팀 밖에 샙니다.
  • 만들다 만 항목은 기본이 "안 보임" 입니다. 켜는 것이 명시적 행위여야 합니다.

리뷰를 안 받아들이면 머지가 막혔다

docs#353머지
  • 규칙이 "reject 한 코멘트는 닫지 않는다" 였는데, 이 저장소는 코멘트가 전부 닫혀야 머지됩니다.
  • 같은 문서의 다른 절은 이미 반대로 적고 있었습니다 — 셋 중 하나만 규칙이 달랐습니다.
  • 검토 기회는 답글이 이미 보존합니다. 열어 둔 코멘트는 기록이 아니라 차단입니다.
  • 대신 닫기 전에 사람에게 선택을 받게 했습니다 — reject 는 셋 중 유일하게 판단만 남는 갈래입니다.
더 한 작업들 — 고치다 만난 것

#354 · 배포가 어드민 데이터를 지울 참이었다

큐레이션 seed 가 전량 삭제 후 재적재였습니다. 어드민이 붙은 지금 그대로 뒀다면 배포 한 번이 넣고 고친 항목을 통째로 지웠습니다. 앞선 PR 에 "그때 걷어내야 한다"고 적어 둔 자리입니다.

#354 · 필드 하나를 빼면 요청 전체가 400 이었다

Jackson 3 은 선택 필드가 primitive 면 그 필드가 없을 때 매핑을 깨뜨립니다. 어드민이 값 하나를 생략한 것이 값 오류로 보고되어 어디가 틀렸는지 알 수 없었습니다. 래퍼로 받고 기본값은 DTO 가 정합니다.

#354 · 삭제가 두 문장이라 404 가 200 이 될 수 있었다

있는지 확인하고 지우는 사이에 다른 어드민이 같은 항목을 지우면 404 여야 할 요청이 200 으로 나갑니다. 지운 행 수로 판정해 그 틈을 없앴습니다. 조회가 하나 주는 건 덤입니다.

#358 · 우리가 무엇을 보내는지 보는 자리가 없었다

FCM 메시지는 내용을 읽을 수 있는 접근자가 없습니다. 조립과 발송을 갈라, SDK 가 전송에 쓰는 직렬화기를 통과한 실제 JSON 으로 확인하게 했습니다. 같은 회귀가 조용히 다시 나가지 않습니다.

#359 · 접미사를 떼면 "동구" 가 "동" 이 된다

프론트가 "서버가 어려우면 앱에서 떼겠다"고 했는데, 89곳을 세어 보니 다섯이 자치구였습니다. 어느 이름이 자치구인지는 이 표를 가진 쪽만 압니다 — 서버가 다듬어 내려보냅니다.

#359 · 코스 없는 알림 하나가 목록 전체를 500 으로 만들었다

불변 맵은 키가 null 이면 조회에서 예외를 냅니다. 코스와 무관한 알림 하나가 목록 응답 전체를 무너뜨렸습니다. 테스트가 먼저 잡았습니다.

기능은 있는데 사용자에게 닿지 않던 것이 이번 주에 셋 나왔습니다. 도로에 안 붙는 좌표가 이동시간을 조용히 직선거리로 떨어뜨리고(#351), 푸시는 발송 성공으로 집계되면서 화면에는 안 뜨고(#358), 알림은 어느 여행인지 말하지 못했습니다(#359). 공통점은 실패가 실패로 안 보였다는 것입니다 — 셋 다 "무엇을 보내고 무엇을 계산했는지" 를 확인하는 자리를 함께 만들었습니다.

배포 없이 고칠 수 있게 — 절반이 끝났다

외부 링크를 배포 없이 관리하는 서버 기능이 완성됐습니다(#354). 다만 지금은 API 뿐이라 curl 로만 쓸 수 있고, 그러면 결국 아무도 안 쓰고 SQL 로 돌아갑니다. 다음은 관리 화면(#343) 과 정책까지 옮기는 일(#344)입니다. 어드민 계정은 아직 비어 있어 지금은 아무도 못 들어갑니다 — 로그인 한 번 뒤에 첫 계정을 넣습니다.
