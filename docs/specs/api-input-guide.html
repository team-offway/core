화면별로 무엇을 입력받나

사용자가 화면에서 주는 값과, 안 주면 어떻게 되는지. 회색 작은 글씨는 개발용 이름.

1홈 화면

아직 아무것도 안 고른 사람에게 인기 여행지를 보여준다. 출발지를 모르니 "몇 시간 걸리는지"는 못 보여주고 방문자 많은 순으로만 나온다.

없음—그냥 뜬다

2연차 넣고 "며칠 놀 수 있나" 계산

사용자가 주는 것필수?없으면
이동수단 — 자차 / 대중교통 transport 필수요청 거부
여행 시작일 + 종료일 startDate·endDate A안둘 중 하나만 주면 거부
기간 버튼 — 당일치기 / 주말 포함 / 연차 이어서 periodStyle B안—
기준 날짜 — "언제부터 찾아줄까" baseDate B안이면 필수요청 거부
주말에 붙일 요일 — 금요일 or 월요일 weekendBridge "주말 포함"일 때만요청 거부
연차 며칠 쓸지 — 2일 or 3일 leaveDays "연차 이어서"일 때만요청 거부
첫날 반차 여부 halfDayStart 선택종일로 계산

A안과 B안은 둘 중 하나만 고른다. 날짜를 직접 찍든지, 버튼을 누르든지. 둘 다 보내면 거부한다 — 안 그러면 사용자가 찍은 날짜가 소리 없이 무시되기 때문이다.

3여행지 추천받기

"어디로 갈지"는 입력받지 않는다. 그걸 찾아주는 단계라, 인구감소지역 89곳 중에서 골라 순위를 매겨 돌려준다.

사용자가 주는 것필수?없으면
출발지 — 내 위치 또는 직접 고른 곳 originLat·originLng 필수요청 거부
이동수단 transport 필수요청 거부
편도 최대 이동시간 maxReachMinutes 필수요청 거부
무드칩 — 맛집 / 관광지 / 숙박 / 체험 mood 선택전체에서 추천

편도 최대 이동시간은 사용자가 직접 입력하지 않는다 — 2단계 계산 결과가 그대로 넘어온다.

주의 — 출발지에서 그 시간 안에 갈 수 있는 곳이 하나도 없으면 빈 목록이 나간다(오류가 아니다). 화면에서 "추천 없음"으로만 처리하면 사용자는 왜 비었는지 모른다. "이동시간을 늘려보세요" 같은 안내가 필요하다.

"다시 돌리기"는 위와 똑같이 보내면 된다. 화면에 안 보이는 내부값 둘(seed·previousSeed)이 더 있는데, 직전과 다른 코스를 뽑는 데만 쓴다.

⚠️ 여행 날짜가 4단계에선 필수인데 저장할 때는 선택이다. 그래서 날짜 없이 저장하면 나중에 연차 차감을 누를 때 실패한다 — 서버가 며칠 빠지는지 계산할 근거가 없다. 코스 만들 때 이미 날짜를 받았으니 저장할 때 그대로 실어 보내면 된다. 예전에 저장된 코스들 때문에 선택으로 열어둔 상태라, 프론트에서는 항상 날짜를 함께 보내는 것이 안전하다.

모든 요청에 인증 헤더가 필요하다 — Authorization: Basic base64(아이디:비밀번호). 없으면 401 이 내려온다.
