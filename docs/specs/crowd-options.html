혼잡도 · 서버가 무엇을 언제 내는가
#394 · 디자인 결정용 · 2판

1판 정정. “12개월 뒤에 된다” 고 적었는데 틀렸습니다. 백필이 과거로 거슬러 가서 첫 실행에 지난 열두 달을 한꺼번에 받습니다 — 배포 5분 뒤면 전부 나옵니다. 기다리는 값은 없습니다.

기준은 관광 밀도(관광객 ÷ 면적)입니다. 그 위에 여섯 가지 표현을 낼 수 있고, 전부 배포 직후부터 채워집니다. 디자인이 무엇을 그릴지에 따라 서버가 무엇을 채울지 정해집니다. 아래 방문자 숫자는 모양을 보이기 위한 예시입니다(면적은 실제값).

① 서버가 언제 무엇을 하나

배포 + 4분

백필 — 지난 12개월을 한 번에

2025-09 ~ 2026-08 을 거슬러 받는다. 앞으로 쌓는 게 아니라 과거를 가져온다. 이미 받은 달은 건너뛰므로 두 번째 배포부터는 아무것도 안 받는다.

= 36콜
한도 1,000 의 3.6%

전 항목이 채워진다

요일 패턴·계절성·여행일 예상까지 전부 나온다. 데이터가 쌓이길 기다리는 값은 없다.

② 무엇을 기준으로 재나 — 관광 밀도

관광객 ÷ 면적 (km²)

“이 지역에 가면 사람이 많나” 는 결국 밀도 질문입니다. 절대 방문자로 재면 “붐빔” 이 “큰 지역” 과 거의 같은 말이 됩니다.

지역일평균 관광객면적 km²밀도절대 순위밀도 순위
울릉군3,00072.941.2하위권상위권

울릉도가 뒤집힙니다. 절대값으로는 하위권인데 실제로는 섬이 꽉 찹니다. 밀도가 체감에 가깝습니다.

대안과 한계

기준말하는 것지금
관광 밀도얼마나 몰려 있나면적 넣으면 됨
절대 관광객총 몇 명지금도 됨
거주인구 대비생활 밀도인구 데이터 없음
자기 평소 대비성수기인가백필 직후 됨

밀도의 한계도 있습니다. 면적이 큰 군은 대부분 산인데 관광객은 읍내에 몰립니다 — 산악 지역이 실제보다 한산해 보입니다. 나중에 “가용 면적” 으로 정교화할 수 있습니다.

면적은 외부 호출이 필요 없습니다. 89행짜리 정적 값이라 시드에 넣으면 끝입니다.

③ 낼 수 있는 표현 — 전부 배포 직후부터

① 뱃지

3단계든 5단계든 서버가 정하기 나름. 목록에서 훑기 좋습니다.

"level": "LOW"  // 또는 5단계
완도군 · 전남광주통합특별시
한산

② 백분위

순위를 %로. “혼잡률 %” 의 안전한 형태입니다 — 0~100 이 고르게 채워집니다.

"percentile": 87
// 89곳 중 87% 보다 밀도가 높다
울릉군 · 경상북도
상위 13% · 붐비는 편

③ 순위

가장 정직하지만 “12위” 가 사용자에게 무슨 뜻인지 애매합니다.

"rank": 12, "outOf": 89
안동시 · 경상북도
12위 / 89곳

④ 자기 대비 — 성수기

지역 크기가 아예 안 걸립니다. “울릉군 기준으로 지금 성수기” 가 성립합니다.

"crowdRate": 82,  // 연중 최대 대비
"peakMonth": 8
완도군 · 9월
82%
연중 최대치의 82%
가장 붐비는 달: 8월

⑤ 요일 패턴

“토요일은 평일의 1.4배”. 며칠에 갈지 정하는 데 직접 쓰입니다.

"weekdayFactor": 1.4
완도군 · 토요일
평일의 1.4배 · 화요일이 가장 한산

⑥ 여행일 기준 예상

④ × ⑤ 를 사용자가 고른 날짜에 적용. 평소 한산해도 그날은 붐빌 수 있습니다.

"expectedLevel": "HIGH"
완도군 · 8월 15일 (토)
붐빔
평소엔 한산하지만 그날은 붐빕니다

④ null 은 언제인가 · 함정

기다리는 값은 없습니다

null 이 나오는 경우는 셋뿐이고, “데이터가 쌓일 때까지” 는 여기 없습니다.

언제왜
배포 직후 4분백필이 아직 안 돌았다
관측이 없는 지역원본에 그 지역이 없다 — 지금은 “한산” 으로 거짓말 중
지난달 미발행그 달만 빈다
관측 없는 지역
정보 없음
뱃지를 안 그린다

“최대값 대비 %” 는 쓰면 안 됩니다

관광 방문자는 롱테일이라 1위를 100%로 두면 대부분이 한 자릿수가 됩니다. 89곳이 인구감소지역이라 왜곡이 더 심합니다. 백분위로 바꾸면 고르게 퍼집니다.

✗ 최대값 대비 %

1위100% 10위31% 40위6% 80위1%

✓ 백분위

1위99 10위89 40위55 80위10

⑤ 제 권고

뱃지 + 백분위 + 성수기, 전부 지금부터

"crowd": {
  "level":         "LOW",     // ① 뱃지
  "percentile":    21,        // ② 게이지·근거
  "crowdRate":     45,        // ④ 이 지역 연중 최대 대비
  "peakMonth":     8,         // ④ 가장 붐비는 달
  "expectedLevel": "HIGH",    // ⑥ 여행일 기준
  "basis":         "DENSITY"  // 무엇으로 쟀는지
}
  • 기준은 관광 밀도(관광객 ÷ 면적). 절대값으로 재면 “붐빔” 이 “큰 지역” 과 같은 말이 됩니다.
  • level 은 percentile 에서 나옵니다. 지금 코드의 어림수 임계(3000·10000)가 통째로 사라집니다.
  • rank·outOf 는 뺐습니다. percentile 이 같은 정보를 더 읽히게 주고 분모가 필요 없습니다.
  • 전부 배포 직후 채워집니다. 기다리는 값이 없습니다.
  • 관측이 없으면 전부 null. “모른다” 를 “한산” 으로 속이지 않습니다 — 앱이 null 을 다뤄야 하는 유일한 변경입니다.
  • 디자인 자유도 — 뱃지만 쓰면 level, 게이지면 percentile, 도넛이면 crowdRate. 전부 한 응답에 있습니다.
